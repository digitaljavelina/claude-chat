**Body — sequential orchestration instructions.** The skill body must instruct Claude to execute these steps in order (per D-10, D-11, D-12):

**Step 1 — Scan for new sessions:**
Run `python3 $HOME/.claude-chat/sync_chats.py scan` via Bash tool. Parse the stdout JSON array. If the array is empty, print "No new sessions to sync." and stop. Otherwise, report how many sessions were found.

**Step 2 — For each session in the delta list, sequentially:**

2a. **Check user message count (per D-05):** Run a Python one-liner via Bash that counts user messages in the JSONL file at the session's `path` field. The one-liner must handle both content formats (plain string and block-list). If count < 2, print "Skipping <session_id>: fewer than 2 user messages" and continue to the next session.

2b. **Extract first ~5 and last ~5 user/assistant message pairs (per D-01):** Use the Read tool to load the JSONL file at the session's `path` field. From the loaded content, identify the first ~5 and last ~5 message pairs where role is "user" or "assistant" and content contains actual text (skip tool_use blocks, skip system-reminder messages). These messages will be presented to Claude as context for labeling.

2c. **Generate labels (per D-02, D-03, D-04, D-06, D-07, D-13, D-14):** Present the extracted messages to Claude with a labeling prompt. The prompt must:

- Include 3-4 few-shot examples of ideal output spanning debugging, setup, writing, and exploration session types
- Instruct Claude to produce a ```json fenced code block containing `{"title": "...", "gist": "...", "tags": [...], "coherence_score": N, "needs_review": false}`
- Title: verb-leading action phrase, max 10 words (noun phrase only for purely exploratory sessions with no clear action)
- Gist: 2-3 sentences, past tense, summarizing what happened
- Tags: 3-5 kebab-case strings as a JSON array
- If the session is mostly automated tool output with little meaningful human conversation, include "low_signal" in tags (per D-06)
- If the conversation covers clearly distinct unrelated topics, include "multi_topic" in tags (per D-07)
- coherence_score: 1-5 integer (5 = single clear topic with resolution, 1 = scattered/abandoned) (per D-13). This is metadata only, not a skip gate (per D-14).
- needs_review: false (unless fallback triggers)

2d. **Extract JSON and write (per D-04, D-12):** After Claude generates the label, extract the JSON from the ```json code block. Construct a Bash command that pipes the label JSON through `python3 $HOME/.claude-chat/sync_chats.py write <session_id>`. Use Python's `json.dumps()` to serialize the label dict safely (avoids shell injection from titles containing quotes/apostrophes — this is the main security concern per RESEARCH.md §Security Domain). The pattern:

```bash
python3 -c "import json; print(json.dumps({...}))" | python3 $HOME/.claude-chat/sync_chats.py write <session_id>
```

Claude fills in the actual label values in the Python dict literal.

2e. **Fallback on parse failure (per D-08):** If the JSON extraction or parsing fails (no ```json block found, or json.loads raises), fall back to `make_stub_label()` immediately with NO retry. The fallback Bash command:

```bash
python3 -c "
import json, sys, pathlib
sys.path.insert(0, str(pathlib.Path.home() / '.claude-chat'))
import sync_chats
label = sync_chats.make_stub_label(pathlib.Path('SESSION_PATH'), 'SESSION_ID')
print(json.dumps(label))
" | python3 $HOME/.claude-chat/sync_chats.py write SESSION_ID
```

Print a warning: "Label generation failed for <session_id>, using stub label."

**Step 3 — Summary:** After all sessions are processed, print a summary line: "Processed N sessions: M labeled, K stubbed, J skipped (ultra-short)."
