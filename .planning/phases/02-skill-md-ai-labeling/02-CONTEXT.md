# Phase 2: SKILL.md + AI Labeling - Context

**Gathered:** 2026-04-13
**Status:** Ready for planning

<domain>
## Phase Boundary

Create a Claude Code skill at `~/.claude/skills/sync-chats/SKILL.md` that replaces Phase 1's stub labels with Claude-generated titles, gists, tags, and coherence scores for every new Claude Code session. The skill orchestrates a sequential scan→label→write loop, feeding labels through the same stdin-JSON contract that `sync_chats.py write` already accepts. Phase 2 does NOT add PII scrubbing (Phase 3), MemPalace integration (Phase 4), or the SessionEnd hook (Phase 5). The skill is invoked manually via `/sync-chats` in any interactive Claude Code session.

</domain>

<decisions>
## Implementation Decisions

### A — Prompt design and content strategy

- **D-01:** The skill feeds Claude the **first ~5 and last ~5 user/assistant message pairs** from each session. This captures the opening question and the resolution while keeping prompt size bounded regardless of session length. The exact N is Claude's discretion (5 is a guideline, not a hard rule).
- **D-02:** Titles are **verb-leading action phrases** (e.g., "Debug RSS feed parsing in homelab service"). ≤10 words per LABEL-03. Verb-leading is the default; Claude may use noun phrases only when the session is purely exploratory with no clear action.
- **D-03:** The labeling prompt includes **3-4 few-shot examples** of ideal title/gist/tags output to anchor Claude's style consistently across sessions. Examples should span different session types (debugging, setup, writing, exploration).
- **D-04:** Claude's label response is a **```json fenced code block** containing `{title, gist, tags, coherence_score}`. The skill extracts the first JSON code block from the response using a simple regex, then parses it. This is more resilient than raw-JSON-only because Claude can include thinking text around the block.

### B — Edge case handling (LABEL-07)

- **D-05:** Ultra-short sessions are detected by **user message count < 2**. If a session has fewer than 2 user messages, the skill skips it entirely (no file written). This catches abandoned sessions where the user typed one thing and never followed up.
- **D-06:** Low-signal detection (mostly tool calls) is **delegated to Claude** via a prompt instruction: "If this session is mostly automated tool output with little meaningful human conversation, include `low_signal` in the tags array." No Python-side heuristic.
- **D-07:** Multi-topic detection is **delegated to Claude** via a prompt instruction: "If the conversation covers clearly distinct unrelated topics, include `multi_topic` in the tags array." No Python-side heuristic.
- **D-08:** When Claude's JSON response is malformed (unparseable), the skill **falls back immediately** to `make_stub_label()` from Phase 1 with no retry. The stub sets `needs_review: true` so the session appears in Obsidian's review queue. One failure = one stub, no latency doubling.

### C — Skill structure and invocation (LABEL-01, LABEL-02)

- **D-09:** The skill lives at `~/.claude/skills/sync-chats/SKILL.md` with frontmatter: `name: sync-chats`, `description: Sync Claude Code sessions to Obsidian vault with AI-generated labels`, `disable-model-invocation: true` (Phase 2 uses Claude in-session, not a separate model call), and `allowed-tools: [Bash, Read]`. No Write tool — all vault writes go through `sync_chats.py`.
- **D-10:** `/sync-chats` accepts **no arguments**. Every invocation does a full scan→label→write loop. No `--dry-run`, no `--label-only`. Re-labeling a single session is deferred to v2 (LABEL-V2-01).
- **D-11:** The skill processes sessions **sequentially, one at a time**: scan → get delta list → for each session: read content via Bash (`sync_chats.py` or direct JSONL read), extract first+last messages, prompt Claude for label, extract JSON from response, pipe to `sync_chats.py write` via Bash. Matches ROADMAP success criterion #1.
- **D-12:** The skill's Bash calls use `python3 ~/.claude-chat/sync_chats.py scan` to get the delta list, and `echo '<label_json>' | python3 ~/.claude-chat/sync_chats.py write <session_id>` to write each session. The skill never writes files directly.

### D — Coherence scoring (LABEL-06)

- **D-13:** `coherence_score` (1–5) is generated by Claude alongside the label, as part of the same JSON response. The prompt instructs Claude to rate how coherent/focused the session was: 5 = single clear topic with resolution, 1 = scattered/abandoned. Downstream use: Obsidian Dataview queries can filter by score (e.g., surface only high-quality sessions for review).
- **D-14:** Coherence score is a soft signal, not a gate. No session is skipped or tagged differently based on the score alone — it's purely metadata for the user to query on.

### Claude's Discretion

The planner and executor have freedom on:

- Exact prompt wording and few-shot example content (the decisions above set the structure and style, not the prose)
- How to extract first+last N messages from a JSONL file (Read tool vs. Bash + Python one-liner vs. a helper function in the skill)
- The exact regex for extracting the JSON code block from Claude's response
- Whether to use `sync_chats.py scan` output directly or re-parse it
- The `argument-hint` text in SKILL.md frontmatter
- How to display progress to the user during a multi-session run (print per-session or batch summary)
- The exact value of N for first/last message pairs (5 is guidance, adjust if sessions are typically shorter)

</decisions>

## Existing Code Insights

### Reusable Assets

- **`sync_chats.py` cmd_write()** (line 732) — reads label JSON from stdin, handles all three clobber defense layers, writes atomically. Phase 2 pipes into this exact interface.
- **`sync_chats.py` make_stub_label()** (line 334) — builds the fallback label dict. Phase 2's LABEL-08 fallback calls this directly (or reimplements the same logic in the skill's Bash).
- **`sync_chats.py` cmd_scan()** — returns JSON array of unsynced sessions on stdout. Phase 2 parses this to get the delta list.
- **`sync_chats.py` extract_first_user_message()** — already extracts the first user message from a JSONL file. Could be extended or the skill can read the JSONL directly via Read tool.

### Established Patterns

- **stdin JSON contract** — Phase 1 established that `write` only accepts labels via stdin JSON. Phase 2 must honor this exactly — no flags, no file paths.
- **Zero external deps** — `sync_chats.py` is stdlib-only. The SKILL.md is a markdown file with Bash blocks, not Python — no dependency concern there.
- **SKILL.md frontmatter** — existing skills like `daily` use `name`, `description` in frontmatter. Phase 2 adds `disable-model-invocation`, `allowed-tools`, `argument-hint`.

### Integration Points

- **SKILL.md → `sync_chats.py scan`** — Bash call to get delta list
- **SKILL.md → JSONL files** — Read tool to load session content for labeling prompt
- **SKILL.md → Claude (in-session)** — the labeling prompt is just text in the skill; Claude processes it as part of the skill execution
- **SKILL.md → `sync_chats.py write`** — Bash call with label JSON piped to stdin
- **Skill location** — `~/.claude/skills/sync-chats/SKILL.md` (global, not project-local)

</code_context>

<specifics>
## Specific Ideas

- "Label-quality bugs and pipeline-correctness bugs stay decoupled" — this is the core Phase 1→2 design principle. Phase 1 proved the pipeline is idempotent with stubs. Phase 2 only changes what labels look like, never how they flow through the pipeline. If labeling produces garbage, the worst case is a bad title — the file still writes correctly, clobber defense still holds, and `needs_review: true` flags it.
- The skill runs inside an interactive Claude session, which means Claude IS the labeler — no API calls, no separate model. The skill's "prompt" is just markdown text that Claude reads as part of executing the skill. This is an unusual pattern worth documenting clearly in SKILL.md.
- Michael is a Python beginner. The SKILL.md itself is Bash + markdown (no Python), but any helper logic should be explained inline.

</specifics>

<deferred>
## Deferred Ideas

- **`--dry-run` flag** — preview labels without writing. Could be useful for testing prompt quality. Deferred to v2.
- **`--label-only <session_id>`** — re-label a single session. Bumps against clobber defense. Deferred to LABEL-V2-01.
- **Configurable prompt template** — currently hardcoded in SKILL.md. Deferred to LABEL-V2-02.
- **Coherence score as a skip gate** — currently score is metadata only. Could add "skip sessions scoring 1" in a future version, but for now all sessions get written.
- **Batch prompting** — feed multiple sessions to Claude at once for faster labeling. Deferred; sequential is simpler and matches success criteria.
- **`--set-label` argument for re-onboarding** — already handled by `sync_chats.py init --label`. Not needed in the skill.

None — discussion stayed within phase scope.

</deferred>
