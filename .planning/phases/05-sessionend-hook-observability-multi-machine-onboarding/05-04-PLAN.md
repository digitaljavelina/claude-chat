<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stdin → cmd_relabel | Untrusted JSON from the SKILL (which gets it from Claude). Already the Phase 1 D-01/D-02 contract — parsed via `json.loads`, title-required validation. |
| vault file → cmd_relabel | Previously-written file under `$VAULT/Chats/`; could be hand-edited. We guard with sentinel-only re-label (D-05). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Tampering | User hand-edits body then runs relabel | mitigate | `auto_label_hash` would no longer match the body's SHA-256 at read time — BUT we're not recomputing-and-comparing here, we're checking `== "stub"` literal. If a user hand-edited a stub file's body, we'd re-label and their edits would PERSIST (body is untouched by design). Acceptable: they asked for a re-label by leaving the sentinel. |
| T-05-04-02 | Tampering | User changes auto_label_hash to "stub" to force re-label of an AI-labeled file | accept | Single-user local tool — user is the attacker model. If they want to re-label their own file, that's fine. |
| T-05-04-03 | Spoofing | cmd_relabel called with session_id that matches multiple vault files | mitigate | Scan for files where frontmatter `session_id` matches; the Phase 1 filename convention (`machine--date--slug.md`) makes collisions possible only across `-2`/`-3` suffixes. Pick the first match; log a warning to stderr if >1 found. |
| T-05-04-04 | Information disclosure | stderr leaks vault path on refusal | accept | Single-user tool, local stderr. |
| T-05-04-05 | Elevation of privilege | relabel is called on an already-labeled file via script | mitigate | D-05 sentinel guard: refuses with exit 1. Test `test_refuses_when_hash_is_real_sha256` enforces. |
</threat_model>
