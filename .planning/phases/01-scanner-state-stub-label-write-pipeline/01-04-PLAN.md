```bash
#!/usr/bin/env bash
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"

PASS=0; FAIL=0
```

**Criterion 3** (CORE-02 -- write): Since the canary cannot use the real claude-chat.py export --stdout (the fake session UUID won't be found in the real ~/.claude/projects/), create a mock approach. Write a small Python wrapper that the canary uses instead of relying on the subprocess bridge:

```bash
echo "Criterion 3: write creates vault file"
# Create a mock claude-chat.py that just outputs markdown for --stdout
MOCK_CLI="$TMPDIR_BASE/mock-claude-chat.py"
cat > "$MOCK_CLI" << 'PYEOF'
import sys
if "--stdout" in sys.argv:
    print("# Claude Code Session: 541112ec\n\n**Date:** 2026-03-19\n\nUser: Debug the export markdown function")
else:
    print("Mock: file export not supported in test")
PYEOF

# Temporarily point sync_chats at the mock
# We need the write command to find our mock. The simplest way is to put the mock
# where sync_chats.py expects claude-chat.py (same directory as sync_chats.py).
# Instead, we override by placing the mock at the path sync_chats.py will check.
cp "$MOCK_CLI" "$PROJECT_DIR/claude-chat.py.bak" 2>/dev/null || true
```

Actually, this approach is fragile. Better approach: since sync_chats.py looks for claude-chat.py relative to its own location (Path(**file**).resolve().parent / "claude-chat.py"), and claude-chat.py exists there, the real claude-chat.py will be called. But it won't find the fake session.

Simplest robust approach: Add a SYNC_CHATS_CLAUDE_CLI env var override to sync_chats.py for the claude-chat.py path (one line in \_get_markdown_body), then point it at a mock in the canary. Change the \_get_markdown_body function to check:

```python
claude_chat_path = Path(os.environ.get("SYNC_CHATS_CLAUDE_CLI", str(Path(__file__).resolve().parent / "claude-chat.py")))
```
